# 06б Кнопки аналітики — Make

Оновлено: 10 листопада 2026 · Юля

## Що це

У службовій групі «Тестування ботів АКМЦ», у гілці **«Аналітика»**, закріплене повідомлення бота «📊 Звіт аналітики на вимогу» з кнопками **Доба / 3 дні / 7 днів / 14 днів / 30 днів**. Натиснули кнопку — за 2–5 хвилин у гілку приходить звіт за цей період. Будь-який інший період — командою `/report 5` (від 1 до 90 днів).

Щотижневий звіт у понеділок о 10:00 від кнопок не залежить: він приходить сам, навіть якщо кнопки зламалися.

## Як це працює

Ланцюжок із трьох ланок:

1. **Telegram.** Хтось натискає кнопку. Telegram одразу надсилає це натискання на адресу Make. Така адреса називається **вебхук** (англ. hook — «гачок»): Make «закинув гачок» і чекає, коли «клюне».
2. **Make.** Отримавши натискання, Make одразу звертається до GitHub: «запусти звіт». Щоб GitHub повірив, що це свої, Make показує **ключ «Make аналітика»** — як перепустку.
3. **GitHub.** Запускає задачу «Аналітика на вимогу (кнопки в боті)». Вона відповідає в Telegram «⏳ Готую звіт…», збирає цифри й надсилає звіт.

| Ланка | Де лежить | Що там важливе |
|---|---|---|
| Кнопки | Telegram, гілка «Аналітика», закріплене повідомлення | Публікує сам бот (див. «Налаштувати з нуля», крок 3) |
| Сценарій Make | Make → **Scenarios** → «АКМЦ — кнопки аналітики» (2 модулі: Webhooks і HTTP) | Має бути **Active** |
| Ключ «Make аналітика» | Лише в Make: модуль HTTP → заголовок Authorization | Діє до **10.11.2027** |
| Задача GitHub | deepstate-tracker → **Actions** → «Аналітика на вимогу (кнопки в боті)» | Файли `ondemand.py` і `.github/workflows/analytics-ondemand.yml` |

## Що робити, якщо кнопки замовкли

Ідіть по ланцюжку зліва направо:

1. **Make → сценарій «АКМЦ — кнопки аналітики».** Чи стоїть угорі **Active**? Якщо **Inactive** — увімкнути. Make сам вимикає сценарій після кількох помилок поспіль.
2. **Make → той самий сценарій → History** (історія запусків). Чи з'являються запуски, коли тиснете кнопку?
   - **Запусків немає** → Telegram не знає адреси Make. Повторіть крок 3 з розділу «Налаштувати з нуля» (Run workflow з адресою вебхука).
   - **Запуск червоний, помилка 401 або «Bad credentials»** → ключ «Make аналітика» сплив або його видалили. Див. «Продовжити ключ».
   - **Помилка 404 або 422** → неправильна адреса (URL) у модулі HTTP або перейменовано файл задачі на GitHub. Звірте з кроком 2 нижче.
3. **GitHub → Actions → «Аналітика на вимогу (кнопки в боті)».** Чи є запуск і чи він зелений? Червоний — відкрити журнал і переслати текст помилки в гілку «Помилки».
4. **Зникло закріплене повідомлення з кнопками** → GitHub → Actions → «Аналітика на вимогу (кнопки в боті)» → **Run workflow** → постав галочку «Опублікувати й закріпити кнопки» → **Run workflow**.

Поки розбираєтеся — звіт можна отримати запасним шляхом: див. «06 Аналітика».

## Продовжити ключ «Make аналітика»

Раз на рік (нагадування в календарі — 03.11.2027) або якщо ключ скомпрометовано.

1. github.com → фото профілю → **Settings** → унизу ліворуч **Developer settings** → **Personal access tokens** → **Fine-grained tokens**.
2. Якщо ключ «Make аналітика» є у списку і створений з вашого акаунта — відкрити його → **Regenerate token** → новий строк (Custom, +1 рік) → **Regenerate token**. Якщо ключа немає (наприклад, його створила інша людина) — створити новий, як у кроці 1 розділу «Налаштувати з нуля».
3. Скопіювати ключ (кнопка з двома квадратиками). Його показують лише один раз.
4. Make → сценарій «АКМЦ — кнопки аналітики» → клацнути на синій кружечок **HTTP** → у **Headers** знайти **Authorization** → у **Value** замінити все після `Bearer ` (зі пробілом) на новий ключ → **Save** → зберегти сценарій (значок дискети або Ctrl+S).
5. Перевірити: натиснути **Доба** в гілці «Аналітика».

Ключ нікому не надсилати і не вставляти більше нікуди.

## Налаштувати з нуля

Знадобиться, якщо сценарій видалили або переносимо в інший акаунт Make. Займає ~20 хвилин.

### Крок 1. Ключ GitHub

github.com → фото профілю → **Settings** → **Developer settings** → **Personal access tokens** → **Fine-grained tokens** → **Generate new token**:

- **Token name:** `Make аналітика`
- **Resource owner:** `Anti-Crisis-Media-Center` (не особистий акаунт!)
- **Expiration:** Custom → дата через рік
- **Repository access:** **Only select repositories** → лише `deepstate-tracker`
- **Permissions** → **Repositories** → **Add permissions** → **Actions:** `Read and write` (Metadata: Read-only додасться сама)
- **Generate token** → скопіювати ключ.

### Крок 2. Сценарій у Make

1. **Create a new scenario** → великий «+» → **Webhooks** → **Custom webhook** → **Add**.
2. **Webhook name:** `Telegram аналітика АКМЦ`. Увімкнути **Advanced settings** → **JSON pass-through:** **Yes**. Решту не чіпати (API keys не додавати) → **Save**.
3. Скопіювати адресу вебхука (`https://hook.eu1.make.com/…`) кнопкою копіювання. Вікно не закривати — Make чекає перший запит («Listening for data»).
4. Виконати **крок 3** (нижче) в іншій вкладці, потім натиснути в Telegram кнопку **Доба**. У Make має з'явитися «Successfully determined» → **Save**.
5. Праворуч від рожевого кружечка — «+» → **HTTP** → **Make a request**:
   - **Authentication type:** **No authentication**
   - **URL:** `https://api.github.com/repos/Anti-Crisis-Media-Center/deepstate-tracker/actions/workflows/analytics-ondemand.yml/dispatches`
   - **Method:** `POST`
   - **Headers:**
     - `Authorization` → `Bearer ` + ключ із кроку 1 (між словом і ключем — один пробіл)
     - `Accept` → `application/vnd.github+json`
   - **Body content type:** `application/json` → **Body input method:** `JSON string`
   - **Body content:** вставити цілим рядком (Ctrl+V) — Make сам перетворить `{{…}}` на кольорові плашки:
     `{"ref":"main","inputs":{"update":"{{base64(1.value)}}"}}`
   - **Parse response:** **No**
   - **Save**.
6. Угорі: розклад **Immediately as data arrives**, перемикач **Active**. Зберегти сценарій (Ctrl+S). Назву сценарію (олівець угорі ліворуч) — «АКМЦ — кнопки аналітики».

### Крок 3. Під'єднати бота до Make

GitHub → deepstate-tracker → **Actions** → ліворуч «**Аналітика на вимогу (кнопки в боті)**» → **Run workflow**:

- **webhook_url:** адреса вебхука з кроку 2;
- галочка «**Опублікувати й закріпити кнопки**»;
- **Run workflow**.

Через хвилину в гілці «Аналітика» з'явиться нове закріплене повідомлення з кнопками. Старе закріплене можна видалити.

Важливо: після цього кроку бот отримує натискання **лише через Make**. Якщо колись захочете відмовитися від Make — напишіть у гілку «Помилки»: задачу треба повернути до старого способу.

## Корисно знати

- Адреса вебхука — не пароль, але публікувати її не варто: хто її знає, може запускати звіти в нашу групу.
- Кожне натискання — 2 операції в Make. Навіть 100 натискань на місяць — 200 операцій.
- Звіт приходить у ту саму гілку «Аналітика», у тому самому форматі, що й щотижневий.
