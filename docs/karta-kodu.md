# 08 Карта коду — що де лежить у репозиторії

*Станом на 12.11.2026, з урахуванням нової версії (v9), що стартує 16.11.2026. Для людини з технічною освітою, яка має щось полагодити або пояснити розробнику, що зламалося.*

## Де код

- **GitHub:** організація **Anti-Crisis-Media-Center**, репозиторій **deepstate-tracker** (публічний). Як отримати доступ — «04 Код і документація».
- **Гілка `main`** — робоча версія: саме вона щодня публікує.
- **Гілка `v9-video`** — нова версія (Reels, відео, нові назви місць). 15.11 її зливають у `main`, після цього гілка не потрібна.
- **Окремо:**
  - бот «Хвилина мовчання» — репозиторій **memorial-bot**;
  - стрічка новин сайту й кнопки аналітики — сценарії **Make**, не GitHub (див. «06б» і «07»).
- **Ключі й паролі в коді не зберігаються.** Усі вони лежать у секретах GitHub: **Settings** → **Secrets and variables** → **Actions**. Що який секрет означає — «01 Доступи і відновлення».

## Папки

| Папка | Що там |
|---|---|
| `.github/workflows/` | Розклад і запуск: коли й що бот робить (таблиця нижче) |
| `data/history.csv` | Головний журнал: один рядок на добу (площі, зміни, повідомлення DeepState, назви місць, підписники). З нього рахуються тижневі й місячні підсумки, а Google-таблиця аналітики бере дані звідси |
| `data/state/` | Останній знімок мапи DeepState (з ним бот порівнює наступного ранку) |
| `data/changes/` | Ділянки, що змінилися за кожну добу (файли `ДАТА.geojson`) — з них малюється мапа й рахуються назви |
| `data/grey/` | Сіра зона («район проникнення») за кожну добу |
| `data/reference/` | Довідники: межі областей, 2 224 населені пункти з районами. Змінюються рідко |
| `assets/fonts/` | Шрифт Montserrat (вільна ліцензія) |
| `assets/music/news.mp3` | Фонова музика для відео — трек Сергія (з 16.11) |
| `docs/` | Копії інструкцій (ці самі тексти, що на Диску) |
| `tests/` | Автоматичні перевірки: чи правильно бот формулює тексти й вибирає назви |

**Важливо:** вміст `data/` бот оновлює сам щоранку. Руками там нічого не правити, бо зіб'ється порівняння.

## tracker.py усередині — розділи

Файл поділено на розділи з помітними заголовками `# ======== НАЗВА ========`. Щоб знайти потрібний, на GitHub відкрий файл і натисни **Ctrl+F**.

| Розділ | Що там |
|---|---|
| `CONFIG` | Налаштування: години публікації, пороги, **список міст** (`CITIES`), тезки за районами (`CITY_DISTRICT`), родовий відмінок міст. Сюди дивитися, якщо треба додати або прибрати місто |
| `DATA SOURCES` | Завантаження мапи DeepState і довідників |
| `ANALYSIS` | Порівняння вчорашньої й сьогоднішньої мапи: що позначено окупованим, деокупованим, сірою зоною |
| `MESSAGES` | Повідомлення з сайту DeepState: які стосуються Донеччини й Луганщини |
| `TEXT` | Тексти щоденного посту (Telegram) |
| `TELEGRAM` | Публікація в канал |
| `FACEBOOK-ТИЗЕР`, `FACEBOOK-СТОРІЗ` | Публікація у Facebook |
| `TIKTOK (ручна публікація)` | Пакет у гілку «TikTok»: відео, тексти, а також **вибір назв місць** — функція `place_names` (одна для всіх форматів) |
| `STATE` | Збереження стану й журналу |
| `SUMMARIES` | Тижневі й місячні підсумки |
| `МІНІ-МАПА ЗМІН` | Підготовка мапи (заголовок, які назви підписати) |
| `MAIN` | Порядок дій щоранку; кожна платформа — окремий крок: збій однієї не зупиняє інших |

## Якщо зламалося — де шукати

| Що бачиш | Де дивитися |
|---|---|
| Уранці немає посту ніде | **Actions** → «DeepState — моніторинг змін» → останній запуск → червоний крок. Часто причина в DeepState (сайт не відповідає) — тоді спрацює запасний запуск о 10:17 |
| Немає лише в одній мережі | Гілка «Помилки» службової групи; у журналі запуску — крок цієї платформи. Найчастіше прострочений ключ (див. «01») |
| Неправильна назва місця або не та назва на мапі | `tracker.py` → `place_names` (вибір назв), `CONFIG` → `CITIES` (що вважається містом); `change_map.py` → підписи на мапі |
| Неправильна цифра | `tracker.py` → розділ `ANALYSIS` (порахунок) і `SUMMARIES` (тиждень/місяць) |
| Криво виглядає картинка | `change_map.py` (мапа), `story.py` (сторіз), `video.py` (відео) |
| Звіт аналітики не прийшов | **Actions** → «Аналітика соцмереж — щотижневий звіт»; `analytics.py` |
| Кнопки аналітики мовчать | Спершу сценарій Make (див. «06б»), потім **Actions** → «Аналітика на вимогу» |

## Як безпечно щось змінити

1. Кожна зміна має пояснювальний коментар у коді, наприклад `# рішення 10.11.2026: …` або `# виправлення 12.11.2026: …`. Тож видно не лише *що* робить рядок, а й *чому* так вирішили. Пошук за датою (Ctrl+F «12.11») показує все, що змінювали того дня.
2. Перевірити, нічого не публікуючи: **Actions** → «DeepState — моніторинг змін» → **Run workflow** → поставити `dry_run` → журнал покаже тексти, які бот опублікував би.
3. Після зміни **Actions** → «tests» має бути зеленим.
4. Будь-яку зміну можна повернути: на GitHub у файлі **History** → попередня версія. Або попросити Claude повернути конкретну зміну за датою.
