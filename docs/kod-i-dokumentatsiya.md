## Які файли давати, залежно від задачі

**Щоб людина / ШІ зрозуміли, як усе влаштовано** — найкраще віддати весь ZIP. Якщо треба менше, то:
- DeepState: `README.md`, уся папка `docs/`, `tracker.py` (головна програма), `change_map.py` (мапа), `story.py` (сторіз), `video.py` (відео), папка `.github/workflows/` (розклад запусків), `requirements.txt`.
- Аналітика: `analytics.py`, `youtube_api.py`, `tiktok_api.py`, `.github/workflows/analytics.yml`.
- Меморіал: `README.md`, папка `docs/`, `memorial.py`, `bot.py`, `post.py`, `card.py`, `regions.py`, `.github/workflows/memorial.yml`.

**Щоб подивитися дані:**
- DeepState: `data/history.csv` — уся історія змін по днях (відкривається в Google Таблицях / Excel).
- Меморіал: `state/published.json` — кого вже опублікували (щоб не повторювати).

**Плюс документи з Диску АКМЦ** (папка «00 Автоматизація АКМЦ — інструкції»): 00, 01, 02, 02а, 03, YouTube-аналітика. Без паролів — їх там і немає.

## Як дати це іншому ШІ-помічнику

1. Завантажити ZIP (посилання вище) і, за потреби, документи з Диску.
2. Додати їх у чат / проєкт помічника.
3. Перше повідомлення, наприклад:
   > «Це код і документація ботів нашої редакції. Спочатку прочитай README.md і папку docs, поясни, як усе працює. Нічого не публікуй і не змінюй, поки ми не домовимося. Будь-які перевірки — лише в тестовому режимі (DRY_RUN / dry_run, mode test).»
4. Ключі ботів помічнику не давати. Якщо він пропонує зміни в коді, їх вносить у GitHub людина з доступом (Тетяна — власниця організації).

## Якщо GitHub недоступний узагалі

- Поки репозиторії публічні, архів завантажується навіть без акаунта.
- Якщо зник сам GitHub-акаунт організації — рятує лише копія. Тому **раз на місяць** завантажуйте обидва ZIP на Диск АКМЦ у папку «Архів коду» (разом з експортом даних Claude). Цього достатньо, щоб розробник відновив ботів на новому акаунті за день.
- Що доведеться відновити вручну: ключі ботів і токени соцмереж (див. «01 Доступи»), бо в архіві їх немає — і це правильно.
